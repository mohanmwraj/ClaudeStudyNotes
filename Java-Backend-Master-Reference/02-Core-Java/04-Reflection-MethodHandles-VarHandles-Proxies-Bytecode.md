## 1. Why this matters for backend engineers

Every framework you use is built on these mechanisms:

| Framework feature | Mechanism |
|---|---|
| Spring DI, `@Autowired`, `@Value` | Reflection (fields, constructors), annotation scanning, CGLIB subclass proxies for `@Configuration`, `@Transactional`, `@Async`, `@Cacheable` |
| Hibernate lazy loading, dirty checking | ByteBuddy proxies (`HibernateProxy`) and bytecode enhancement |
| Jackson | Reflection for discovery, then `MethodHandle`/`LambdaMetafactory` accessors (Blackbird) or generated bytecode (Afterburner) |
| Mockito | ByteBuddy, inline mock maker via `Instrumentation` (retransforms classes, so it can mock finals) |
| OpenTelemetry Java agent, APM tools | `java.lang.instrument` agents rewriting bytecode at load time |
| Lombok, MapStruct, Dagger, Micronaut | Compile-time annotation processing (JSR 269) |
| javac-generated code | `invokedynamic` for lambdas, string concat, records, pattern switch |

Understanding these mechanisms is how you debug "my `@Transactional` doesn't work", `InaccessibleObjectException` after a JDK upgrade, proxy-related Metaspace growth, and 30% CPU in `Method.invoke`.

## 2. Core reflection internals ⚡

* `Class` caches its reflective data (`ReflectionData`, held through a `SoftReference`). `getDeclaredMethods()`/`getMethods()` return **fresh copies** of `Method` objects on every call, which allocates arrays and objects. **Cache `Method`/`Field` objects** in `static final` fields or maps.
* **JDK 18, JEP 416:** `Method.invoke`, `Constructor.newInstance` and `Field.get/set` are reimplemented on **method handles** (`DirectMethodHandleAccessor`). The old scheme (native accessor for 15 calls, then bytecode generation, "inflation") is gone. When the `Method` object is a **constant** (`static final`), C2 can inline right through `invoke`.
* `invoke` still boxes arguments into `Object[]` and boxes the return value. Escape analysis removes that only when everything inlines.
* Exceptions thrown by the target are wrapped in `InvocationTargetException`. Unwrap with `getCause()`.
* `setAccessible(true)` suppresses **language** access checks (private and so on), but **module encapsulation** still applies: `InaccessibleObjectException` unless the package is `opens`ed to the caller. `trySetAccessible()` returns `false` instead of throwing.
* **Caller-sensitive methods** (`Class.forName`, `Method.invoke`, `MethodHandles.lookup()`) inspect the caller's class. That's why `Lookup` objects must not be leaked to untrusted code.

### 2.1 Runnable: what an invocation costs

<!-- run: timeout=120 -->
```java
import java.lang.invoke.*;
import java.lang.reflect.Method;
import java.util.function.ToIntFunction;

public class InvokeCost {
    public static final class Target { private final int v; Target(int v) { this.v = v; } public int value() { return v; } }

    static final Method METHOD;
    static final MethodHandle MH_CONST;
    static MethodHandle mhField;                                   // NOT final → not constant-foldable by the JIT
    static final ToIntFunction<Target> LMF;
    static {
        try {
            METHOD = Target.class.getMethod("value");
            MH_CONST = MethodHandles.lookup().findVirtual(Target.class, "value", MethodType.methodType(int.class));
            mhField = MH_CONST;
            CallSite site = LambdaMetafactory.metafactory(MethodHandles.lookup(), "applyAsInt",
                MethodType.methodType(ToIntFunction.class), MethodType.methodType(int.class, Object.class),
                MH_CONST, MethodType.methodType(int.class, Target.class));
            @SuppressWarnings("unchecked") ToIntFunction<Target> f = (ToIntFunction<Target>) site.getTarget().invokeExact();
            LMF = f;                                                  // a real functional-interface object over the getter
        } catch (Throwable t) { throw new ExceptionInInitializerError(t); }
    }

    interface Body { long run(Target[] ts) throws Throwable; }

    static void bench(String name, Target[] ts, Body b) throws Throwable {
        long best = Long.MAX_VALUE, sink = 0;
        for (int i = 0; i < 15; i++) { long t = System.nanoTime(); sink += b.run(ts); best = Math.min(best, System.nanoTime() - t); }
        System.out.printf("%-34s %6.2f ns/call%s%n", name, best / (double) ts.length, sink == 42 ? "!" : "");
    }

    public static void main(String[] args) throws Throwable {
        Target[] ts = new Target[1_000_000];
        for (int i = 0; i < ts.length; i++) ts[i] = new Target(i);
        bench("direct call", ts, a -> { long s = 0; for (Target t : a) s += t.value(); return s; });
        bench("static final MethodHandle", ts, a -> { long s = 0; for (Target t : a) s += (int) MH_CONST.invokeExact(t); return s; });
        bench("LambdaMetafactory ToIntFunction", ts, a -> { long s = 0; for (Target t : a) s += LMF.applyAsInt(t); return s; });
        bench("static final Method.invoke", ts, a -> { long s = 0; for (Target t : a) s += (Integer) METHOD.invoke(t); return s; });
        bench("non-final MethodHandle field", ts, a -> { long s = 0; for (Target t : a) s += (int) mhField.invokeExact(t); return s; });
        bench("getMethod() + invoke every call", ts, a -> { long s = 0; for (Target t : a) s += (Integer) Target.class.getMethod("value").invoke(t); return s; });
    }
}
```

Two measured runs (JDK 25):

```
direct call                          0.87 ns/call     0.93
static final MethodHandle            0.92 ns/call     0.97     ← constant-folded and inlined, ≈ direct
LambdaMetafactory ToIntFunction      0.93 ns/call     0.92     ← what Jackson Blackbird does
static final Method.invoke           1.28 ns/call     1.31     ← JEP 416: constant Method inlines too (since JDK 18)
non-final MethodHandle field         3.53 ns/call     3.25     ← opaque handle: generic invoker path
getMethod() + invoke every call     28.98 ns/call    27.35     ← lookup + copying + access checks each time
```

**Takeaways:**

1. **Lookup is the expensive part.** Cache reflective objects once, in `static final` fields when possible.
2. Handles and reflection held in **mutable or instance fields** can't be constant-folded. Frameworks that store accessors per class in maps pay the "non-final" price, which is still cheap in absolute terms.
3. Generating a real functional-interface instance (`LambdaMetafactory`) gives direct-call speed and a type the JIT handles well (monomorphic `applyAsInt`), as long as the call site stays monomorphic.

## 3. Annotations ⚡🎓

| Retention | Stored in class file? | Visible via reflection? | Example |
|---|---|---|---|
| `SOURCE` | No | No | `@Override`, `@SuppressWarnings`, Lombok's annotations |
| `CLASS` (default) | Yes (`RuntimeInvisibleAnnotations`) | **No** | Bytecode tools, `@Nullable` variants for static analysis |
| `RUNTIME` | Yes (`RuntimeVisibleAnnotations`) | Yes | `@Transactional`, `@Entity`, `@JsonProperty` |

* `@Target` (`TYPE`, `METHOD`, `FIELD`, `PARAMETER`, `TYPE_USE`, `RECORD_COMPONENT`, …), `@Inherited` (only for **class** annotations, only via superclasses, never interfaces), `@Repeatable(Container.class)` (read with `getAnnotationsByType`), `@Documented`.
* Annotation element types: primitives, `String`, `Class`, enums, other annotations, and 1-D arrays of these. Defaults must be compile-time constants.
* At run time, annotation instances are **dynamic proxies** (`Proxy` + `AnnotationInvocationHandler`), parsed lazily from the class file and cached per class.
* **Compile time vs run time:** runtime classpath scanning (Spring's `@ComponentScan`) costs startup time, while compile-time processing (JSR 269 `Processor`s: MapStruct, Dagger, Micronaut, Spring AOT, `spring-boot-configuration-processor`) moves the work to the build.

<!-- run: -->
```java
import java.lang.annotation.*;
import java.util.Arrays;

public class AnnotationsDemo {
    @Retention(RetentionPolicy.RUNTIME) @Target(ElementType.METHOD) @Repeatable(Roles.class)
    @interface Role { String value(); }
    @Retention(RetentionPolicy.RUNTIME) @Target(ElementType.METHOD)
    @interface Roles { Role[] value(); }
    @Retention(RetentionPolicy.CLASS) @interface Invisible {}
    @Retention(RetentionPolicy.RUNTIME) @Inherited @interface Audited { int level() default 1; }

    @Audited(level = 3) static class Base {}
    static class Child extends Base {}

    static class Api {
        @Role("admin") @Role("ops") @Invisible
        public void deleteTenant() {}
    }

    public static void main(String[] args) throws Exception {
        var m = Api.class.getMethod("deleteTenant");
        System.out.println("roles = " + Arrays.toString(Arrays.stream(m.getAnnotationsByType(Role.class)).map(Role::value).toArray()));
        System.out.println("getAnnotation(Role) = " + m.getAnnotation(Role.class) + "  (wrapped in the container)");
        System.out.println("CLASS-retention visible? " + (m.getAnnotation(Invisible.class) != null));
        System.out.println("@Inherited on Child: level=" + Child.class.getAnnotation(Audited.class).level());
        Annotation a = m.getAnnotation(Roles.class);
        System.out.println("annotation instance class: " + a.getClass().getName().replaceAll("\\d+", "N")
            + " isProxy=" + java.lang.reflect.Proxy.isProxyClass(a.getClass()));
    }
}
```

Output (verified):

```
roles = [admin, ops]
getAnnotation(Role) = null  (wrapped in the container)
CLASS-retention visible? false
@Inherited on Child: level=3
annotation instance class: $ProxyN isProxy=true
```

(These annotation types are non-public nested types, so their proxy class is defined in the same unnamed package. Annotations declared public in exported packages get `jdk.proxyN.$ProxyN`.)

## 4. Method handles (`java.lang.invoke`) 🔥

### 4.1 Concepts

| Concept | Meaning |
|---|---|
| `MethodHandles.Lookup` | A **capability** carrying the access rights of the class that created it. `lookup()` has full privileges for the caller. `publicLookup()` sees only public members of exported packages. `privateLookupIn(target, lookup)` gives deep access if the module `opens` it |
| `MethodType` | Exact signature, e.g. `(Target)int` |
| `findVirtual/findStatic/findSpecial/findConstructor/findGetter/findSetter/findStaticGetter/findVarHandle/unreflect` | Obtain direct handles |
| `invokeExact` | **Signature-polymorphic**: the call-site's *symbolic* type must match exactly, including the return type cast. A mismatch throws `WrongMethodTypeException` |
| `invoke` | Adapts with `asType` (boxing, widening, casts) per call. Slower unless the JIT folds it |
| Combinators | `bindTo`, `insertArguments`, `dropArguments`, `filterArguments`, `filterReturnValue`, `foldArguments`, `permuteArguments`, `guardWithTest`, `catchException`, `tryFinally`, `countedLoop`, `iteratedLoop`, `constant`, `identity`, `throwException` |
| `CallSite` | `ConstantCallSite` (linked once), `MutableCallSite`/`VolatileCallSite` (re-linkable: the JIT recompiles dependent code when the target changes) |
| LambdaForms | Internal IR that the JIT inlines through; a constant handle chain becomes straight-line code |

### 4.2 Runnable: building logic from combinators

<!-- run: -->
```java
import java.lang.invoke.*;
import static java.lang.invoke.MethodType.methodType;

public class HandleCombinators {
    static String greet(String greeting, String name) { return greeting + ", " + name + "!"; }
    static boolean isVip(String name) { return name.startsWith("vip:"); }
    static String vip(String name) { return "Welcome back, " + name.substring(4) + " ★"; }
    static String fallback(RuntimeException e, String name) { return "error handled for " + name + ": " + e.getMessage(); }
    static String explode(String name) { if (name.isEmpty()) throw new IllegalArgumentException("empty name"); return name; }

    public static void main(String[] args) throws Throwable {
        var L = MethodHandles.lookup();
        MethodHandle greet = L.findStatic(HandleCombinators.class, "greet", methodType(String.class, String.class, String.class));

        MethodHandle hello = MethodHandles.insertArguments(greet, 0, "Hello");          // partial application
        MethodHandle upper = L.findVirtual(String.class, "toUpperCase", methodType(String.class));
        MethodHandle shout = MethodHandles.filterReturnValue(hello, upper);              // compose
        System.out.println((String) shout.invokeExact("ann"));

        MethodHandle test = L.findStatic(HandleCombinators.class, "isVip", methodType(boolean.class, String.class));
        MethodHandle vip = L.findStatic(HandleCombinators.class, "vip", methodType(String.class, String.class));
        MethodHandle router = MethodHandles.guardWithTest(test, vip, hello);           // if/else as a handle
        System.out.println((String) router.invokeExact("vip:bob") + " | " + (String) router.invokeExact("cat"));

        MethodHandle risky = L.findStatic(HandleCombinators.class, "explode", methodType(String.class, String.class));
        MethodHandle safe = MethodHandles.catchException(MethodHandles.filterReturnValue(risky, hello),
            RuntimeException.class, L.findStatic(HandleCombinators.class, "fallback", methodType(String.class, RuntimeException.class, String.class)));
        System.out.println((String) safe.invokeExact("") + " | " + (String) safe.invokeExact("dan"));

        try { Object wrong = shout.invokeExact("ann"); }                                 // return type is Object, not String
        catch (WrongMethodTypeException e) { System.out.println("invokeExact type mismatch → " + e.getClass().getSimpleName()); }
        Object adapted = shout.invoke("eve");                                           // invoke adapts via asType
        System.out.println("invoke() adapts: " + adapted);

        MutableCallSite flag = new MutableCallSite(MethodHandles.constant(boolean.class, false));
        MethodHandle featureOn = flag.dynamicInvoker();
        System.out.print("feature: " + (boolean) featureOn.invokeExact());
        flag.setTarget(MethodHandles.constant(boolean.class, true));                    // relink: JIT deopts dependents
        System.out.println(" → " + (boolean) featureOn.invokeExact());
    }
}
```

Output (verified):

```
HELLO, ANN!
Welcome back, bob ★ | Hello, cat!
error handled for : empty name | Hello, dan!
invokeExact type mismatch → WrongMethodTypeException
invoke() adapts: HELLO, EVE!
feature: false → true
```

**`MutableCallSite` as a feature flag:** compiled code that calls `dynamicInvoker()` treats the current target as a **constant**: zero-cost checks, dead branches removed. Calling `setTarget` deoptimizes and recompiles the dependents, so it is ideal for rarely flipped switches (kill switches, logging levels). This is how dynamic-language runtimes implement inline caches.

## 5. VarHandles — the sanctioned replacement for `Unsafe` field access 🔥

### 5.1 Access modes (memory-ordering strength increases downward)

| Mode | Read | Write | Semantics (C++11 analogue) |
|---|---|---|---|
| **Plain** | `get` | `set` | Like normal field access: no ordering, may tear for `long`/`double` on 32-bit |
| **Opaque** | `getOpaque` | `setOpaque` | Coherent per variable and never optimized away (`memory_order_relaxed`); for progress flags and counters read by monitors |
| **Acquire/Release** | `getAcquire` | `setRelease` | Release: earlier accesses can't move after it. Acquire: later accesses can't move before it. Enough for **message passing / safe publication** (single producer → consumer) |
| **Volatile** | `getVolatile` | `setVolatile` | Sequentially consistent: same as a `volatile` field (`memory_order_seq_cst`) |
| **Atomic RMW** | — | `compareAndSet`, `compareAndExchange[Acquire\|Release]`, `weakCompareAndSet[Plain\|Acquire\|Release]` (may fail spuriously; use in retry loops), `getAndSet`, `getAndAdd`, `getAndBitwiseOr/And/Xor` | CAS family |
| Fences | `VarHandle.fullFence()`, `acquireFence()`, `releaseFence()`, `loadLoadFence()`, `storeStoreFence()` | | Explicit barriers |

The memory-model meaning of these modes is covered in Pillar 3 ([3.1 JMM](../03-Concurrency-Loom/01-Java-Memory-Model.md)).

### 5.2 Runnable: field CAS, array element atomics, and endian-aware byte views

<!-- run: -->
```java
import java.lang.invoke.MethodHandles;
import java.lang.invoke.VarHandle;
import java.nio.ByteOrder;
import java.util.Arrays;
import java.util.HexFormat;

public class VarHandleTour {
    static class Account { volatile long balance; int version; }

    static final VarHandle BALANCE, VERSION, LONGS, BE_INT, LE_INT;
    static {
        try {
            var l = MethodHandles.lookup();
            BALANCE = l.findVarHandle(Account.class, "balance", long.class);
            VERSION = l.findVarHandle(Account.class, "version", int.class);
            LONGS = MethodHandles.arrayElementVarHandle(long[].class);
            BE_INT = MethodHandles.byteArrayViewVarHandle(int[].class, ByteOrder.BIG_ENDIAN);
            LE_INT = MethodHandles.byteArrayViewVarHandle(int[].class, ByteOrder.LITTLE_ENDIAN);
        } catch (ReflectiveOperationException e) { throw new ExceptionInInitializerError(e); }
    }

    static boolean withdraw(Account a, long amount) {                // lock-free conditional update
        long current;
        do {
            current = (long) BALANCE.getVolatile(a);
            if (current < amount) return false;
        } while (!BALANCE.compareAndSet(a, current, current - amount));
        VERSION.getAndAdd(a, 1);                                      // atomic RMW on a NON-volatile int field
        return true;
    }

    public static void main(String[] args) {
        Account acc = new Account(); acc.balance = 100;
        System.out.println(withdraw(acc, 30) + " " + withdraw(acc, 80) + " balance=" + acc.balance + " version=" + acc.version);

        long[] counters = new long[4];
        LONGS.getAndAdd(counters, 2, 5L);                            // AtomicLongArray-style ops on a plain array
        LONGS.setRelease(counters, 0, 9L);
        System.out.println("counters=" + Arrays.toString(counters) + " cmpxchg witness=" + (long) LONGS.compareAndExchange(counters, 2, 5L, 6L));

        byte[] wire = HexFormat.of().parseHex("0000002A01000000");   // network bytes
        System.out.println("big-endian int @0 = " + (int) BE_INT.get(wire, 0) + ", little-endian int @4 = " + (int) LE_INT.get(wire, 4));
        BE_INT.set(wire, 0, 0xCAFEBABE);
        System.out.println("after write: " + HexFormat.of().formatHex(wire));
    }
}
```

Output (verified):

```
true false balance=70 version=1
counters=[9, 0, 5, 0] cmpxchg witness=5
big-endian int @0 = 42, little-endian int @4 = 1
after write: cafebabe01000000
```

### 5.3 Migrating off `sun.misc.Unsafe` (JEP 471 / 498) 🔥

`Unsafe`'s memory-access methods are **deprecated for removal** (JDK 23) and **warn at run time** since JDK 24 (`--sun-misc-unsafe-memory-access=allow|warn|debug|deny`; the default became `warn`). You already saw the real warning in Pillar 1 when JOL ran:

```
WARNING: A terminally deprecated method in sun.misc.Unsafe has been called
WARNING: sun.misc.Unsafe::arrayBaseOffset has been called by org.openjdk.jol.vm.HotspotUnsafe (file:/…/jol-cli.jar)
WARNING: Please consider reporting this to the maintainers of class org.openjdk.jol.vm.HotspotUnsafe
WARNING: sun.misc.Unsafe::arrayBaseOffset will be removed in a future release
```

| `Unsafe` usage | Replacement |
|---|---|
| `getInt/putInt(obj, offset)`, `objectFieldOffset` | `VarHandle` (`findVarHandle`) |
| `compareAndSwapInt/Long/Object` | `VarHandle.compareAndSet` / `Atomic*` / `Atomic*FieldUpdater` |
| `putOrderedInt` (lazySet) | `VarHandle.setRelease` |
| `getIntVolatile` | `VarHandle.getVolatile` |
| `loadFence/storeFence/fullFence` | `VarHandle.acquireFence/releaseFence/fullFence` |
| `allocateMemory/freeMemory/getLong(address)` | FFM: `Arena` + `MemorySegment` ([1.2 §8](../01-JVM-Internals/02-Runtime-Data-Areas-Off-Heap-FFM.md#8-the-foreign-function--memory-api-jdk-22-jep-454-)) |
| `copyMemory` | `MemorySegment.copy` |
| `allocateInstance` (skip constructors) | No direct replacement; Objenesis falls back on `ReflectionFactory`. Avoid where possible |
| `park/unpark` | `LockSupport` |
| `defineAnonymousClass` (removed in 17) | `Lookup.defineHiddenClass` |

## 6. Dynamic proxies 🔥

### 6.1 JDK `java.lang.reflect.Proxy`

* `Proxy.newProxyInstance(loader, interfaces, handler)` generates (and caches per loader + interface list) a class `$ProxyN` that **implements the interfaces**. If every interface is public and in an exported package, the class goes into a **dynamic module** `jdk.proxyN` (JDK 16+). If any interface is non-public, the proxy class must be defined **in that interface's package and module**; the demo below shows both. Every method, plus `equals`, `hashCode` and `toString`, calls `handler.invoke(proxy, Method, Object[] args)`.
* Costs: an `Object[]` for arguments, boxing, a `Method` dispatch, and typically a reflective call to the target. Usually negligible compared with the I/O behind a service call.
* **Only interfaces** can be proxied.
* A checked exception thrown by the handler that isn't declared by the interface method gets wrapped in `UndeclaredThrowableException`. Unwrap `InvocationTargetException` and rethrow the cause.
* Default interface methods: `InvocationHandler.invokeDefault(proxy, method, args)` (JDK 16).

### 6.2 Runnable: a logging/timing proxy, and the self-invocation trap

<!-- run: -->
```java
import java.lang.reflect.*;
import java.util.ArrayList;
import java.util.List;

public class ProxyDemo {
    interface OrderService {
        String place(String item);
        String placeAndAudit(String item);             // internally calls place(...)
        default String version() { return "v1"; }
    }

    static class OrderServiceImpl implements OrderService {
        public String place(String item) { return "placed " + item; }
        public String placeAndAudit(String item) { return place(item) + " +audited"; }   // SELF-INVOCATION via `this`
    }

    static final List<String> intercepted = new ArrayList<>();

    @SuppressWarnings("unchecked")
    static <T> T traced(T target, Class<T> iface) {
        InvocationHandler h = (proxy, method, args) -> {
            intercepted.add(method.getName());
            if (method.isDefault()) return InvocationHandler.invokeDefault(proxy, method, args);
            try { return method.invoke(target, args); }
            catch (InvocationTargetException e) { throw e.getCause(); }   // never leak the reflective wrapper
        };
        return (T) Proxy.newProxyInstance(iface.getClassLoader(), new Class<?>[] {iface}, h);
    }

    public static void main(String[] args) {
        OrderService svc = traced(new OrderServiceImpl(), OrderService.class);
        System.out.println(svc.place("book"));
        System.out.println(svc.placeAndAudit("pen"));
        System.out.println(svc.version());
        System.out.println("intercepted calls: " + intercepted + "  ← place() inside placeAndAudit() was NOT intercepted");
        Class<?> pc = svc.getClass();
        System.out.println("proxy class: " + pc.getName().replaceAll("\\d+", "N") + ", isProxyClass=" + Proxy.isProxyClass(pc)
            + ", named module=" + pc.getModule().isNamed() + "  (non-public interface → proxy lives in ITS package)");
        Runnable r = (Runnable) Proxy.newProxyInstance(ProxyDemo.class.getClassLoader(), new Class<?>[] {Runnable.class}, (p, m, a) -> null);
        System.out.println("public java.lang.Runnable proxy: " + r.getClass().getName().replaceAll("\\d+", "N")
            + " in module " + r.getClass().getModule().getName().replaceAll("\\d+", "N"));
    }
}
```

Output (verified):

```
placed book
placed pen +audited
v1
intercepted calls: [place, placeAndAudit, version]  ← place() inside placeAndAudit() was NOT intercepted
proxy class: $ProxyN, isProxyClass=true, named module=false  (non-public interface → proxy lives in ITS package)
public java.lang.Runnable proxy: jdk.proxyN.$ProxyN in module jdk.proxyN
```

> **The self-invocation trap** (the #1 Spring AOP bug, detailed in [6.1](../06-Spring-Microservices/01-Spring-Container-Internals-IoC-AOP.md) and, for `@Transactional`, [5.4](../05-Persistence-JPA-Hibernate/04-Transactions-Isolation-Locking-Spring-Transactional.md)): a proxy wraps the object **from the outside**. When the target calls its own method via `this`, the call never passes through the proxy, so `@Transactional`, `@Cacheable`, `@Async` and `@Retryable` on the inner method **silently do nothing**. Fixes: move the method to another bean, inject the proxy into itself (`@Lazy` self-reference), use `TransactionTemplate` programmatically, or use AspectJ load-time or compile-time weaving.

### 6.3 Subclass proxies: CGLIB and ByteBuddy

| | JDK Proxy | CGLIB (Spring-repackaged) | ByteBuddy |
|---|---|---|---|
| Mechanism | Implements interfaces | **Generates a subclass** overriding methods | Generates subclasses, or **redefines/rebases** classes; can use an agent to retransform |
| Proxy classes without interfaces | ❌ | ✅ | ✅ |
| `final` classes/methods | n/a | ❌ (can't override) | ❌ for subclassing (✅ with inline instrumentation, as in Mockito) |
| `private` / `static` methods | ❌ | ❌ | Only via redefinition |
| Constructor | n/a | Called (or skipped via Objenesis) | Configurable |
| Users | Spring (when `proxyTargetClass=false` and an interface exists), Retrofit, MyBatis mappers | Spring `@Configuration`, Spring AOP (Spring Boot defaults to `proxyTargetClass=true`) | Hibernate ORM, Mockito, Byteman, many agents |

**Consequence for Kotlin and records users:** classes are `final` by default, so subclass proxies fail ("Cannot subclass final class"). Spring's Kotlin `allopen` plugin exists for this reason.

<!-- run: cp=byte-buddy -->
```java
import net.bytebuddy.ByteBuddy;
import net.bytebuddy.implementation.MethodDelegation;
import net.bytebuddy.implementation.bind.annotation.*;
import net.bytebuddy.matcher.ElementMatchers;
import java.lang.reflect.Method;
import java.util.concurrent.Callable;

public class SubclassProxy {
    public static class PaymentService {                     // no interface → JDK Proxy impossible
        public String charge(long cents) { return "charged " + cents; }
        public final String id() { return "svc-1"; }          // final: cannot be intercepted by a subclass
    }

    public static class TimingInterceptor {
        @RuntimeType
        public static Object intercept(@Origin Method m, @SuperCall Callable<?> zuper) throws Exception {
            long t = System.nanoTime();
            try { return "[timed] " + zuper.call(); }
            finally { System.out.println("  " + m.getName() + " took " + ((System.nanoTime() - t) >= 0 ? "≥0" : "?") + " ns"); }
        }
    }

    public static void main(String[] args) throws Exception {
        Class<? extends PaymentService> proxyType = new ByteBuddy()
            .subclass(PaymentService.class)
            .method(ElementMatchers.named("charge").or(ElementMatchers.named("id")))
            .intercept(MethodDelegation.to(TimingInterceptor.class))
            .make()
            .load(SubclassProxy.class.getClassLoader())
            .getLoaded();
        PaymentService svc = proxyType.getDeclaredConstructor().newInstance();
        System.out.println(svc.charge(500));
        System.out.println(svc.id() + "  ← final method: not intercepted");
        System.out.println("proxy is a subclass: " + (svc.getClass().getSuperclass() == PaymentService.class)
            + ", name=" + svc.getClass().getSimpleName().replaceAll("\\$[A-Za-z0-9]+$", "\\$…"));
    }
}
```

Output (verified with byte-buddy 1.18.16):

```
  charge took ≥0 ns
[timed] charged 500
svc-1  ← final method: not intercepted
proxy is a subclass: true, name=SubclassProxy$PaymentService$ByteBuddy$…
```

**Metaspace note:** each generated proxy class costs Metaspace. Generating a proxy *class* per instance or per request, instead of caching the type per target class, is a classic Metaspace leak ([1.1 §7](../01-JVM-Internals/01-ClassLoading-Linking-JPMS.md#7-class-unloading-and-loader-leaks-)).

## 7. Bytecode and the Class-File API ⚡

### 7.1 Class file essentials (JVMS §4)

```
ClassFile {
  u4 magic = 0xCAFEBABE;  u2 minor_version;  u2 major_version;   // JDK 21 = 65, JDK 25 = 69 (minor 0xFFFF = preview features)
  constant_pool[]   (Utf8, Integer, Class, String, Fieldref, Methodref, InterfaceMethodref, NameAndType,
                     MethodHandle, MethodType, InvokeDynamic, Dynamic (condy), Module, Package, …)
  access_flags, this_class, super_class, interfaces[], fields[], methods[]
  attributes[]: SourceFile, InnerClasses, NestHost/NestMembers, BootstrapMethods, Record, PermittedSubclasses,
                Module, RuntimeVisibleAnnotations, Signature (generics), …
  method attributes: Code { max_stack, max_locals, code[], exception_table[], StackMapTable, LineNumberTable, LocalVariableTable }
}
```

| Instruction | Used for | Dispatch |
|---|---|---|
| `invokestatic` | Static methods | Direct |
| `invokespecial` | Constructors, `super.m()`, (pre-11) private methods | Direct |
| `invokevirtual` | Instance methods on classes (and private methods since JDK 11 nestmates) | vtable |
| `invokeinterface` | Interface methods | itable (more expensive when megamorphic) |
| `invokedynamic` | Lambdas, string concat, records' `ObjectMethods`, pattern switch | Bootstrap-linked `CallSite` |

`javap -c -p -v MyClass` is your x-ray. Earlier files show real javap for [string concat and switch](02-Strings-Records-Sealed-Pattern-Matching.md#13-concatenation-invokedynamic-since-jdk-9-jep-280-), [records and pattern switch](02-Strings-Records-Sealed-Pattern-Matching.md#53-how-its-compiled-typeswitch--matchexception), and [lambdas](03-Lambdas-Streams-Collectors-Gatherers.md#11-translation-javac).

### 7.2 Runnable: transforming a class with the Class-File API (JDK 24+)

The JDK now ships its own bytecode library (`java.lang.classfile`), so tools no longer need a shaded ASM that lags new class-file versions. Below we **transform** a compiled method: rewrite every `ldc "hello"` into `ldc "HELLO (patched)"`, then load the result as a hidden class.

<!-- run: -->
```java
import java.lang.classfile.*;
import java.lang.classfile.instruction.ConstantInstruction;
import java.lang.constant.ClassDesc;
import java.lang.constant.MethodTypeDesc;
import java.lang.invoke.MethodHandles;
import java.lang.invoke.MethodType;
import static java.lang.constant.ConstantDescs.*;

public class ClassFileTransform {
    public static void main(String[] args) throws Throwable {
        ClassDesc greeter = ClassDesc.of("ClassFileTransformGreeter");
        byte[] original = ClassFile.of().build(greeter, cb -> cb
            .withFlags(ClassFile.ACC_PUBLIC | ClassFile.ACC_FINAL)
            .withMethodBody("greet", MethodTypeDesc.of(CD_String), ClassFile.ACC_PUBLIC | ClassFile.ACC_STATIC,
                code -> code.ldc("hello").areturn()));

        ClassModel model = ClassFile.of().parse(original);
        System.out.println("parsed: " + model.thisClass().asInternalName() + " v" + model.majorVersion()
            + " methods=" + model.methods().stream().map(m -> m.methodName().stringValue()).toList());

        CodeTransform patchConstant = (builder, element) -> {
            if (element instanceof ConstantInstruction.LoadConstantInstruction ldc
                    && "hello".equals(ldc.constantValue())) builder.ldc("HELLO (patched)");
            else builder.with(element);
        };
        byte[] patched = ClassFile.of().transformClass(model, ClassTransform.transformingMethodBodies(patchConstant));

        for (byte[] bytes : new byte[][] {original, patched}) {
            var lookup = MethodHandles.lookup().defineHiddenClass(bytes, true);
            var greet = lookup.findStatic(lookup.lookupClass(), "greet", MethodType.methodType(String.class));
            System.out.println((String) greet.invokeExact());
        }
    }
}
```

Output (verified):

```
parsed: ClassFileTransformGreeter v69 methods=[greet]
hello
HELLO (patched)
```

The same `ClassTransform` API is what an agent's `ClassFileTransformer` would apply at load time (next section). Stack maps are recomputed automatically.

## 8. Java agents (`java.lang.instrument`) 🧊

<!-- run: compile -->
```java
public final class TimingAgent {
    public static void premain(String args, java.lang.instrument.Instrumentation inst) {      // -javaagent:agent.jar=args
        inst.addTransformer(new java.lang.instrument.ClassFileTransformer() {
            @Override public byte[] transform(Module module, ClassLoader loader, String className,
                                              Class<?> redefined, java.security.ProtectionDomain pd, byte[] classfile) {
                if (className == null || !className.startsWith("com/acme/")) return null;      // null = unchanged
                return instrument(classfile);           // e.g. a ClassFile API transform as in §7.2
            }
        }, /* canRetransform */ true);
    }
    public static void agentmain(String args, java.lang.instrument.Instrumentation inst) { premain(args, inst); } // dynamic attach
    static byte[] instrument(byte[] b) { return b; }
}
// MANIFEST.MF: Premain-Class: TimingAgent / Agent-Class: TimingAgent / Can-Retransform-Classes: true
```

* **Load-time** (`-javaagent`) is the supported path. **Dynamic attach** (`agentmain` via the Attach API) prints a warning since JDK 21 (JEP 451) and will be disallowed by default in a future release, unless you run with `-XX:+EnableDynamicAgentLoading`. Mockito's inline mock maker is the most common case, so add `-javaagent:mockito-core.jar` (or the flag) to test JVMs.
* Retransformation can't add fields or methods, or change signatures. Only method bodies change.
* Each retransformation deoptimizes affected compiled code, and instrumentation enlarges methods (risking inlining limits), so APM agents have measurable overhead. JDK 25's JFR method timing (JEP 520) covers many "time this method" needs without an agent.

## 9. Production failure modes & diagnostics

| Failure | Signature | Fix |
|---|---|---|
| `InaccessibleObjectException: Unable to make field … accessible: module java.base does not "opens java.lang"` | After a JDK 17+ upgrade | Upgrade the library; as a last resort `--add-opens` (documented) |
| `@Transactional`/`@Async` "ignored" | Self-invocation; private/final methods with CGLIB | Call through the proxy; public non-final methods; programmatic templates |
| `UndeclaredThrowableException` in logs | Proxy handler threw a checked exception not declared by the interface | Unwrap `InvocationTargetException`; declare or convert exceptions |
| Reflection hot in CPU profiles | `Class.getMethod`, `getDeclaredFields` per request (custom mappers, validation) | Cache `Method`/`Field`/`MethodHandle`; generate accessors once |
| Metaspace growth | `$Proxy`/`ByteBuddy`/`CGLIB` class counts rising (`jcmd GC.class_histogram`, `VM.classloader_stats`) | Cache generated types; don't create proxies per request |
| `Unsafe` warnings at startup (JDK 24+) | `WARNING: A terminally deprecated method in sun.misc.Unsafe has been called` | Upgrade libraries (Netty, Kryo, LZ4, Hazelcast, Arrow…); track with `--sun-misc-unsafe-memory-access=debug` |
| Agent startup warning or failure | `WARNING: A Java agent has been loaded dynamically` | Load agents with `-javaagent`; `-XX:+EnableDynamicAgentLoading` for test tooling |
| `VerifyError` after instrumentation | Broken stack maps or invalid bytecode from a tool | Use the Class-File API/ASM with frame computation; update agents for new class-file versions |
| `IncompatibleClassChangeError` with a shaded ASM | Old ASM in a library can't read class version 69 | Upgrade ASM/ByteBuddy; the JDK Class-File API avoids this |

## 10. Interview Q&A

<details><summary><b>Q1. 🔥 How did JEP 416 change reflection performance, and how should frameworks cache reflective access?</b></summary>

Core reflection now delegates to method handles. There's no "inflation" phase, and a `Method` held in a `static final` field can be inlined by C2 almost like a direct call (measured: 1.28 ns vs 0.87 ns direct). The expensive part is the lookup: `getMethod` copies and checks access (~28 ns per call). Frameworks should resolve members once, then cache `MethodHandle`s or generate `LambdaMetafactory` functional objects for hot accessors.
</details>

<details><summary><b>Q2. 🔥 JDK dynamic proxy vs CGLIB/ByteBuddy: how do they differ and what can't each proxy?</b></summary>

JDK proxies implement interfaces and dispatch every call through an `InvocationHandler`, so they can't proxy classes. CGLIB/ByteBuddy generate subclasses that override methods, so they can proxy classes but not `final` classes or methods, and not private or static methods. Neither intercepts **self-invocation** through `this`, because both wrap the object from outside.
</details>

<details><summary><b>Q3. ⚡ What's the difference between `invokeExact` and `invoke`?</b></summary>

`invokeExact` requires the call site's symbolic type descriptor, including casts on the return value, to match the handle's `MethodType` exactly, or it throws `WrongMethodTypeException`. It is the fastest path. `invoke` allows conversions (boxing, widening, reference casts) by applying `asType` adaptation, which costs more unless the JIT can fold it.
</details>

<details><summary><b>Q4. 🔥 Name the VarHandle access modes from weakest to strongest and when you'd use acquire/release.</b></summary>

Plain → opaque → acquire/release → volatile, plus the atomic RMW operations. Use release on the writer side and acquire on the reader side for **one-way publication**: a producer writes data, then `setRelease(flag, true)`, and the consumer does `getAcquire(flag)` and then reads the data. This is cheaper than volatile on weakly-ordered CPUs (ARM), since it avoids the full StoreLoad barrier, while still guaranteeing the consumer sees the data.
</details>

<details><summary><b>Q5. ⚡ What replaces `Unsafe.allocateMemory` and `Unsafe.compareAndSwapLong`?</b></summary>

`Arena.allocate`/`MemorySegment` (FFM API, JDK 22) for off-heap memory, with deterministic, bounds-checked access. `VarHandle.compareAndSet` (or `AtomicLong`/`AtomicLongFieldUpdater`) for CAS.
</details>

<details><summary><b>Q6. 🎓 What's the difference between `@Retention(CLASS)` and `@Retention(RUNTIME)`? Does `@Inherited` work on interfaces?</b></summary>

`CLASS` annotations are recorded in the class file but not visible through reflection. `RUNTIME` annotations are visible via reflection. `@Inherited` only makes **class-level** annotations inherited by **subclasses**. It has no effect for interfaces or for method annotations.
</details>

<details><summary><b>Q7. 🧊 How does `MutableCallSite` allow near-zero-cost feature flags?</b></summary>

Code linked to `callSite.dynamicInvoker()` treats the current target as a constant: the JIT inlines it and eliminates dead branches. Changing the target with `setTarget` invalidates (deoptimizes) the compiled code that depends on it, so the next compilation uses the new target. Checks are therefore free until the rare flip.
</details>

<details><summary><b>Q8. ⚡ Why did the JDK add its own Class-File API?</b></summary>

Frameworks embedded ASM (often shaded), which must be updated for every new class-file version, roughly every 6 months. Lagging copies break on new JDKs. The JDK's `java.lang.classfile` (final in JDK 24) evolves with the JDK, provides immutable models with builders and transforms, and computes stack maps automatically.
</details>

<details><summary><b>Q9. 🔥 Your `@Cacheable` method is never cached. Name three possible causes.</b></summary>

(1) Self-invocation: called from another method of the same bean via `this`. (2) The method is `private`, or `final` (CGLIB can't override it), or the bean isn't a Spring-managed proxy (created with `new`). (3) The proxy type doesn't expose the method (JDK proxy over an interface that doesn't declare it), or caching isn't enabled (`@EnableCaching` missing). Bonus: key collisions or an `unless`/`condition` evaluating to false.
</details>
