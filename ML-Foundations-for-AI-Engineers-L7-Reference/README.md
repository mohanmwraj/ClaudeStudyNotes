# ML Foundations for AI Engineers — L7 Reference

A first-principles knowledge base for a Senior/Staff backend engineer becoming a Staff/Principal **AI engineer**. It covers the math, classical ML, deep-learning mechanics and statistical evaluation that sit underneath production LLM systems: semantic routers, hybrid search re-ranking, embedding compression, guardrail classifiers, hallucination detection, cost/latency cascades and systematic evals. It isn't a research curriculum. Every formula is tied to a production decision, and every subtopic is tagged:

- `[MUST-KNOW: Core AI Engineer Edge]`
- `[GOOD-TO-KNOW: Architectural Literacy]`
- `[SKIP: Academic/Research Only]`

Every quantitative claim is either **measured by a listing that ships in the file**, **quoted from a verified source** (listed in each file's §8), or marked ⚠.

## Verification harness (Folder 01)

- CPython 3.14.5; NumPy 2.5.4, SciPy 1.18.1, scikit-learn 1.9.1 (session site-dir); PyTorch 2.14.1+cu130, used on CPU with one thread.
- `OPENBLAS_NUM_THREADS=1`. One BLAS thread keeps laptop load low *and* fixes the floating-point reduction order, so seeded outputs reproduce byte for byte.
- All embeddings are **synthetic and seeded**. They reproduce the *mechanisms* (anisotropy, low intrinsic dimension, confusable intents, overconfidence) exactly. Magnitudes on real models differ, and the text says where.
- Gate: listings are extracted from the markdown, checked byte-identical to the sources, rerun sequentially, and compared to the recorded outputs (exact for deterministic listings, digit-masked for timing listings). Structure checks: sections 0–8, a tier tag on every `### 1.x`, all five chain parts, ≥ 8 chains per file.

## Where this KB refines the brief

1. **Files are written straight to disk**, so the per-file `### FILE:` chat headers aren't needed: the folder *is* the repository.
2. **Folder names follow the brief's tree** (`01-Linear-Algebra-Probability-and-Embedding-Geometry/` …), not the shorter names in the role text.
3. **The research ran inline and sequentially** instead of the stock multi-agent deep-research fan-out, to respect the standing no-parallel-local-agents rule on this laptop. Sources were fetched and checked one at a time.
4. **"1/1000th the cost of GPT/Claude" is a range, not a constant.** Measured on published prices (2026-10): a classification call costs **113×** an embedding call on Claude Haiku 5.5, **2,267×** on Sonnet 5.5 and **4,533×** on Opus 5.5 (01.1 §2). A self-hosted encoder takes the embedding side toward pure compute cost.
5. **Temperature is no longer an API knob on current Claude models.** API version 2026-10-21 rejects `temperature`/`top_p`/`top_k`. 01.3 therefore teaches temperature for self-hosted sampling, post-hoc calibration and training losses, and teaches consistency through other means.
6. **Log-prob-based hallucination detection is availability-limited** (no log-probs from Claude, and inconsistent support on reasoning models elsewhere ⚠). 01.3 centres sampling + semantic clustering and grounding checks, with log-probs as an optional extra.
7. **Matryoshka vs PCA is reported honestly.** In the linear toy, corpus-fitted PCA matches MRL at small dims. MRL's production edge is having no fitted projection to version, refit or drift-monitor (01.2 §1.11).
8. **Binary-quantization speedups depend on the engine.** NumPy's popcount path is only ~2× faster than BLAS float32. The ~25× figure (Hugging Face) needs SIMD popcount kernels. The 32× memory saving holds either way.
9. **Chains add a fifth part, "Bar-Raiser Follow-ups"**, because the brief asked for Q&A *chains*: each defense is followed by the interviewer's next questions and their answers.
