# Environment and templates (C++ and Java, Windows 11)

> **Band:** all · **Priority:** 🔥 (set this up in week 1, then never think about it again) · **FAANG:** low · **Prerequisites:** none
> **You can say you know this when:** you can open a new problem, have the samples downloaded and a template compiled in under a minute, run a stress test in either shell, and you know exactly which compiler and flags Codeforces will use on your submission.

This file is the reference for every code block in the kit: C++ programs use the C++ template below (C++20, fast streams), Java programs use the
`FastReader` from the Java template (Java 21). Both templates are compiled and tested by the kit's harness.

## 1. First principles — what the environment is for

A contest environment has exactly three jobs: **(1) turn an idea into a submitted program with the fewest keystrokes and no I/O bugs, (2) find
your bugs before the judge does, (3) behave like the judge** (same language standard, same integer sizes, same stack, same speed class).
Everything below serves one of those:

- the **templates** remove I/O boilerplate and the classic slow-I/O and overflow traps (job 1);
- the **debug macro, sanitiser/debug builds and stress-test scripts** find bugs (job 2);
- the **compile flags** copy what Codeforces does (job 3): it judges on Windows, links C++ with a 256 MB stack and runs Java with specific JVM
  flags — details from the Codeforces command-lines post in §2.

Opinion, widely shared among strong competitors (not verified in this research): keep the template **short**. Algorithms belong in a separate
library you paste on demand (each kit topic file has reference implementations), not in a 500-line header that you no longer understand.

What follows from this table:

1. **Solutions run under Windows** (also stated in the official contest rules, [blog entry 4088](https://codeforces.com/blog/entry/4088)). Windows-only
   behaviours matter: no `getchar_unlocked`, `long double` is the 80-bit x87 type under MinGW G++, and `%lld` with old MinGW `printf` was
   historically unreliable — use streams (the last two are standard knowledge, not verified in this research).
2. **Pick a 64-bit G++ (G++20 or G++23)**: 64-bit arithmetic is native, `__int128` is available, and you get the newer standard library.
3. **The C++ stack is 256 MB** (`--stack=268435456`), so recursion depth $10^6$ is fine on the judge. Your local build must use the same flag or
   deep recursion will crash *only on your machine*.
4. **`ONLINE_JUDGE` is defined** for C++ and set as a system property for Java — the templates use it to switch off debug output.
5. **Java runs with `-XX:TieredStopAtLevel=1`**: only the C1 JIT compiler, so tight loops are slower than on a default local JVM. Measure Java
   timings locally with the same flag (§4). The main thread already gets `-Xss64M`; for deeper recursion use the `Thread` trick from
   [recursion](../01-Foundations/04-recursion-brute-force-and-backtracking.md).

**Rules that affect templates and tools** (both read from the official posts on 23 Oct 2026):

- *Third-party code* ([blog entry 8790](https://codeforces.com/blog/entry/8790)): solutions may only use code written by you, except code that was
  **written and published before the round started** (or generated by tools published before the round), and its use must not violate the
  author's licence. Your own template and library are fine.
- *AI* ([blog entry 133941](https://codeforces.com/blog/entry/133941), revision 2024-09-14): during rated rounds you may not use AI systems to
  produce solution logic, code for the problem or a sub-problem, or to debug from judge feedback; direct translation of statements and
  completion tools for syntax/boilerplate are allowed. Outside contests, AI use for learning is unrestricted. Read the full post — the
  boundaries are specific.

## 3. The templates

### 3.1 C++ template

```cpp
#include <bits/stdc++.h>
using namespace std;

using ll = long long;
using ull = unsigned long long;
using ld = long double;
using pii = pair<int, int>;
using pll = pair<ll, ll>;
#define all(x) (x).begin(), (x).end()
#define sz(x) (int)(x).size()

#ifdef LOCAL
// Debug printing, compiled only with -DLOCAL: prints names and values of ints, strings, pairs, tuples, any container (nested).
template <class T> concept Printable = requires(ostream& os, const T& x) { os << x; };
template <class A, class B> void dprint(const pair<A, B>& p);
template <class... T> void dprint(const tuple<T...>& t);
template <class T> requires (!Printable<T>) void dprint(const T& v);
template <class T> requires Printable<T> void dprint(const T& x) { cerr << x; }
template <class A, class B> void dprint(const pair<A, B>& p) { cerr << '('; dprint(p.first); cerr << ", "; dprint(p.second); cerr << ')'; }
template <class... T> void dprint(const tuple<T...>& t) {
    cerr << '(';
    apply([](const auto&... xs) { int i = 0; ((cerr << (i++ ? ", " : ""), dprint(xs)), ...); }, t);
    cerr << ')';
}
template <class T> requires (!Printable<T>) void dprint(const T& v) {
    cerr << '{';
    bool first = true;
    for (const auto& x : v) { if (!first) cerr << ", "; first = false; dprint(x); }
    cerr << '}';
}
template <class... T> void dbgAll(const char* names, const T&... xs) {
    cerr << "[" << names << "] = ";
    int i = 0;
    ((cerr << (i++ ? " | " : ""), dprint(xs)), ...);
    cerr << '\n';
}
#define dbg(...) dbgAll(#__VA_ARGS__, __VA_ARGS__)
#else
#define dbg(...) ((void)0)
#endif

void solve() {
    int n;
    cin >> n;
    vector<ll> a(n);
    for (auto& x : a) cin >> x;
    dbg(n, a);                              // prints only in LOCAL builds
    cout << accumulate(all(a), 0LL) << '\n';
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int t = 1;
    cin >> t;                               // delete this line for single-test problems
    while (t--) solve();
}
```

```java
import java.io.*;
import java.util.*;

public class Main {
    // Debug output only when run locally with the environment variable LOCAL set and not on the judge.
    static final boolean LOCAL = System.getProperty("ONLINE_JUDGE") == null && System.getenv("LOCAL") != null;

    static void solve(FastReader in, PrintWriter out) throws IOException {
        int n = in.nextInt();
        long[] a = new long[n];
        for (int i = 0; i < n; i++) a[i] = in.nextLong();
        dbg("n", n, "a", a);
        long sum = 0;
        for (long x : a) sum += x;
        out.println(sum);
    }

    public static void main(String[] args) throws IOException {
        FastReader in = new FastReader(System.in);
        PrintWriter out = new PrintWriter(new BufferedWriter(new OutputStreamWriter(System.out), 1 << 16));
        int t = in.nextInt();               // delete for single-test problems
        while (t-- > 0) solve(in, out);
        out.flush();                        // the only flush; never forget it
    }

    static void dbg(Object... xs) {
        if (LOCAL) System.err.println(Arrays.deepToString(xs));
    }

    static final class FastReader {
        private final DataInputStream in;
        private final byte[] buf = new byte[1 << 16];
        private int len = 0, ptr = 0;

        FastReader(InputStream is) { in = new DataInputStream(is); }

        private int read() throws IOException {
            if (ptr == len) {
                len = in.read(buf, 0, buf.length);
                ptr = 0;
                if (len <= 0) { len = 0; return -1; }
            }
            return buf[ptr++];
        }

        private int skip() throws IOException {      // first non-whitespace byte, or -1 at end of input
            int c = read();
            while (c != -1 && c <= ' ') c = read();
            return c;
        }

        long nextLong() throws IOException {
            int c = skip();
            boolean neg = c == '-';
            if (neg) c = read();
            long r = 0;                               // accumulate as a negative number so Long.MIN_VALUE parses
            while (c >= '0' && c <= '9') { r = r * 10 - (c - '0'); c = read(); }
            return neg ? r : -r;
        }

        int nextInt() throws IOException { return (int) nextLong(); }

        double nextDouble() throws IOException { return Double.parseDouble(next()); }

        String next() throws IOException {
            int c = skip();
            if (c == -1) return null;
            StringBuilder sb = new StringBuilder();
            while (c > ' ') { sb.append((char) c); c = read(); }
            return sb.toString();
        }
    }
}
```

Design notes:

- **Multi-test by default.** Most modern Codeforces problems have $t$ test cases; deleting one line is faster than adding a loop.
- **Everything per test lives inside `solve`**: no global arrays to forget to reset (when you do need globals, see the reset patterns in
  [complexity](../01-Foundations/01-complexity-and-constraint-reading.md)).
- **`dbg` costs nothing on the judge** — the macro expands to nothing without `-DLOCAL`, and Java checks a constant.
- **The Java reader** reads raw bytes (no regex, no `String` per token for numbers), handles negative numbers and `Long.MIN_VALUE`, and returns
  `-1`/`null` at end of input instead of looping forever. Why not `Scanner`, `StreamTokenizer`: see [fast I/O](../01-Foundations/06-integer-overflow-precision-and-fast-io.md).
- **Deep recursion in Java**: wrap the body of `main` in `new Thread(null, runnable, "solver", 1 << 28)` (256 MB stack) — shown in
  [recursion §3.4](../01-Foundations/04-recursion-brute-force-and-backtracking.md).

### 3.2 Interactive skeleton

Interactive problems need a flush after every query and must read the judge's reply before continuing
([interactive problems](../03-Greedy-Constructive-Interactive/05-interactive-problems.md)). This skeleton plays "guess a hidden number in $[1, n]$"
with "<" / ">" / "=" replies:

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    long long n;
    cin >> n;
    long long lo = 1, hi = n;
    while (true) {
        long long mid = lo + (hi - lo) / 2;
        cout << "? " << mid << endl;        // endl flushes: required in interactive problems
        string reply;
        cin >> reply;
        if (reply == "=") { cout << "! " << mid << endl; break; }
        if (reply == "<") hi = mid - 1; else lo = mid + 1;   // "<": the hidden number is smaller than mid
    }
}
```

```java
import java.io.*;
import java.util.*;

public class Main {
    public static void main(String[] args) throws IOException {
        BufferedReader br = new BufferedReader(new InputStreamReader(System.in));
        PrintWriter out = new PrintWriter(new BufferedWriter(new OutputStreamWriter(System.out)));
        long n = Long.parseLong(br.readLine().trim());
        long lo = 1, hi = n;
        while (true) {
            long mid = lo + (hi - lo) / 2;
            out.println("? " + mid);
            out.flush();                     // flush after EVERY query
            String reply = br.readLine().trim();
            if (reply.equals("=")) { out.println("! " + mid); out.flush(); break; }
            if (reply.equals("<")) hi = mid - 1; else lo = mid + 1;
        }
    }
}
```

## 4. Building and running locally (Windows 11)

**Toolchains** (versions deliberately not pinned — install whatever is current):

- **C++ on Windows:** a MinGW-w64 GCC build (for example from WinLibs or MSYS2) — the same family Codeforces uses. Put its `bin` folder on `PATH`.
- **C++ under WSL2 (Ubuntu):** GCC with working AddressSanitizer/UBSan and `gdb`; use it for memory bugs.
- **Java:** a JDK 21 (for example Eclipse Temurin). Codeforces offers Java 21.

**Compile commands.**

```bash
# everyday build: same standard, warnings that catch real bugs, 256 MB stack like Codeforces, LOCAL debug on
g++ -std=c++20 -O2 -Wall -Wextra -Wshadow -Wconversion -DLOCAL -Wl,--stack=268435456 -o sol sol.cpp

# debug build on Windows (MinGW): bounds-checked STL + trap on undefined behaviour (no runtime library needed)
g++ -std=c++20 -O1 -g -DLOCAL -D_GLIBCXX_DEBUG -D_GLIBCXX_DEBUG_PEDANTIC \
    -fsanitize=undefined -fsanitize-undefined-trap-on-error -Wl,--stack=268435456 -o sol_dbg sol.cpp

# debug build under WSL2: full sanitizers with readable reports
g++ -std=c++20 -O1 -g -DLOCAL -fsanitize=address,undefined -fno-omit-frame-pointer -o sol_dbg sol.cpp

# Java: compile once, run with the judge's JIT setting to get realistic timings
javac Main.java
java -XX:+UseSerialGC -XX:TieredStopAtLevel=1 -Xss64M -Xmx256m -cp . Main < in.txt
LOCAL=1 java -cp . Main < in.txt         # Git Bash: enable dbg() output
```

Checked with this kit's toolchain (WinLibs MinGW-w64 GCC 16.2): `-fsanitize=address` and plain `-fsanitize=undefined` **fail to link** on
MinGW (`cannot find -lasan` / `-lubsan`), while `-D_GLIBCXX_DEBUG` reports out-of-bounds `vector` indexing and
`-fsanitize=undefined -fsanitize-undefined-trap-on-error` stops the program on a signed overflow (exit code 132, "illegal instruction").
`-ftrapv` also aborts on signed overflow. `_GLIBCXX_DEBUG` makes the STL much slower — use it for small tests only.

PowerShell equivalents: the same `g++`/`javac`/`java` commands work; set the variable with `$env:LOCAL = "1"` before `java`, and use
`Get-Content in.txt | java -cp . Main` or `cmd /c "java -cp . Main < in.txt"` for redirection (PowerShell 5.1 has no `<` operator).

## 5. Stress testing (find the bug before the judge does)

The loop: **generator** prints a random small test for a given seed → run your **solution** and a **brute force** → compare → stop at the first
difference and show the test. Both scripts below were run while writing this kit (a planted bug was caught on the first seed; the fixed
solution passed). Put `gen.cpp`, `brute.cpp` and either `sol.cpp` or `Main.java` in one folder.

**Git Bash (`stress.sh`):**

```bash
#!/usr/bin/env bash
# usage: ./stress.sh [iterations]
# Folder must hold brute.cpp, gen.cpp and either sol.cpp or Main.java (Java wins if both exist).
# gen must take the seed as its only argument and print one test.
set -euo pipefail
CXX="${CXX:-g++} -std=c++20 -O2 -static"
$CXX -o brute brute.cpp
$CXX -o gen gen.cpp
if [[ -f Main.java ]]; then
    javac Main.java
    SOL="java -Xss256m -cp . Main"
else
    $CXX -o sol sol.cpp
    SOL="./sol"
fi
N="${1:-1000}"
for ((i = 1; i <= N; i++)); do
    ./gen "$i" > in.txt
    $SOL < in.txt > out_sol.txt
    ./brute < in.txt > out_brute.txt
    if ! diff -q -w out_sol.txt out_brute.txt > /dev/null; then
        echo "MISMATCH on seed $i"
        echo "--- input";  cat in.txt
        echo "--- sol";    cat out_sol.txt
        echo "--- brute";  cat out_brute.txt
        exit 1
    fi
done
echo "OK: $N random tests passed"
```

**PowerShell (`stress.ps1`):**

```powershell
# usage (from the folder that holds brute.cpp, gen.cpp and sol.cpp or Main.java):
#   powershell -ExecutionPolicy Bypass -File .\stress.ps1 -Iterations 1000
# gen.exe must take the random seed as its only argument and print one test to stdout.
param([int]$Iterations = 1000, [string]$Cxx = "g++", [string[]]$ExtraFlags = @())
function Build($name) {
    & $Cxx @ExtraFlags -std=c++20 -O2 -static -o "$name.exe" "$name.cpp"
    if ($LASTEXITCODE -ne 0) { Write-Host "compile failed: $name.cpp"; exit 2 }
}
Build "brute"; Build "gen"
if (Test-Path "Main.java") {
    javac Main.java
    if ($LASTEXITCODE -ne 0) { Write-Host "compile failed: Main.java"; exit 2 }
    $sol = "java -Xss256m -cp . Main"
} else {
    Build "sol"; $sol = ".\sol.exe"
}
function Run($cmdline) {
    # cmd.exe redirection keeps bytes unchanged (PowerShell 5.1 '>' would re-encode as UTF-16)
    cmd /c $cmdline
    if ($LASTEXITCODE -ne 0) { Write-Host "runtime error (exit $LASTEXITCODE): $cmdline"; Get-Content in.txt; exit 3 }
}
function Tokens($path) { ((Get-Content $path -Raw) -split '\s+' | Where-Object { $_ -ne '' }) -join ' ' }
for ($i = 1; $i -le $Iterations; $i++) {
    Run ".\gen.exe $i > in.txt"
    Run "$sol < in.txt > out_sol.txt"
    Run ".\brute.exe < in.txt > out_brute.txt"
    if ((Tokens "out_sol.txt") -ne (Tokens "out_brute.txt")) {
        Write-Host "MISMATCH on seed $i"
        Write-Host "--- input";  Get-Content in.txt
        Write-Host "--- sol";    Get-Content out_sol.txt
        Write-Host "--- brute";  Get-Content out_brute.txt
        exit 1
    }
}
Write-Host "OK: $Iterations random tests passed"
```

Details that cost time when you get them wrong (all hit while testing these scripts):

- **`-static`**: without it, executables built by MinGW need the compiler's DLLs on `PATH`; launched from another shell they die with exit code
  `-1073741515` (`0xC0000135`, DLL not found).
- **`.\gen.exe`, not `gen.exe`, inside `cmd /c`**: with the environment variable `NoDefaultCurrentDirectoryInExePath` set (some tools set it),
  `cmd` does not search the current folder.
- **Redirection in PowerShell 5.1**: `>` writes UTF-16 text, which a C++ program reads as garbage; route redirections through `cmd /c` as above.
- **Compare tokens, not bytes**: trailing spaces and `\r\n` vs `\n` differ between programs (`diff -w` / the `Tokens` function handle it).
- **The brute force must be obviously correct** — simplest possible code, no shared helper functions with the solution.
- **Small tests find bugs; large tests find TLE.** Generate $n\le 8$ with small values for correctness; time one maximal test separately.

### 5.1 Generator templates

```cpp
#include <bits/stdc++.h>
using namespace std;
using ll = long long;

mt19937_64 rng;
ll rnd(ll lo, ll hi) { return lo + (ll)(rng() % (unsigned long long)(hi - lo + 1)); }   // uniform enough for testing

int main(int argc, char* argv[]) {
    rng.seed(argc > 1 ? stoull(argv[1]) : 1);         // the seed makes every failing test reproducible
    int t = 1;
    cout << t << '\n';
    int n = rnd(1, 8);
    cout << n << '\n';
    for (int i = 0; i < n; i++) cout << rnd(-10, 10) << " \n"[i == n - 1];

    // random permutation of 1..n
    vector<int> p(n);
    iota(p.begin(), p.end(), 1);
    shuffle(p.begin(), p.end(), rng);

    // random tree on n vertices: parent of v is a random earlier vertex, then relabel by the permutation
    vector<pair<int, int>> edges;
    for (int v = 2; v <= n; v++) edges.push_back({p[v - 1], p[rnd(1, v - 1) - 1]});
    shuffle(edges.begin(), edges.end(), rng);

    // k distinct values from [1, 1e9]
    set<ll> distinct;
    while ((int)distinct.size() < n) distinct.insert(rnd(1, 1'000'000'000));

    // random string over a small alphabet (small alphabets create more collisions = more bugs found)
    string s;
    for (int i = 0; i < n; i++) s += char('a' + rnd(0, 2));
    (void)edges; (void)s;
}
```

```java
import java.util.*;

public class Gen {
    public static void main(String[] args) {
        long seed = args.length > 0 ? Long.parseLong(args[0]) : 1;
        Random rng = new Random(seed);
        StringBuilder sb = new StringBuilder();
        int n = 1 + rng.nextInt(8);
        sb.append(1).append('\n').append(n).append('\n');
        for (int i = 0; i < n; i++) sb.append(rng.nextInt(21) - 10).append(i == n - 1 ? '\n' : ' ');
        int[] p = new int[n];                                    // random permutation of 1..n
        for (int i = 0; i < n; i++) p[i] = i + 1;
        for (int i = n - 1; i > 0; i--) { int j = rng.nextInt(i + 1); int t = p[i]; p[i] = p[j]; p[j] = t; }
        List<int[]> edges = new ArrayList<>();                   // random tree
        for (int v = 2; v <= n; v++) edges.add(new int[]{p[v - 1], p[rng.nextInt(v - 1)]});
        Collections.shuffle(edges, rng);
        System.out.print(sb);
    }
}
```

A generator for a problem prints exactly the input format; the extra snippets (permutation, tree, distinct values, string) are there to copy from.

## 7. Pragmas and other speed tricks — caveats

`#pragma GCC optimize("O3,unroll-loops")` and `#pragma GCC target("avx2,bmi,bmi2,popcnt")` (placed before the includes) sometimes give a
constant-factor speed-up on loop-heavy code, and they are widely used by strong competitors. Caveats (standard knowledge, not verified in this research):

1. They do not change complexity; an $O(n^2)$ solution for $n = 2\cdot10^5$ still fails.
2. A `target` pragma emits instructions the judge CPU must support; on a machine without them the program dies with an illegal-instruction
   runtime error. It is a judge-specific bet — and the 32-bit G++ entry on Codeforces is a different machine model again.
3. Some GCC versions report errors with certain `target` pragmas combined with standard headers; if compilation fails, drop the pragma.
4. Measure: compile both versions, time a maximal test locally.

Safer constant-factor wins, in order: avoid `endl` and `Scanner`; flat arrays instead of `vector<vector<>>` for big grids; avoid `map`/`set` in hot
loops; `reserve()`; iterate memory in order; replace `%` by a conditional subtraction in tight modular loops.

## 8. Checklist before you submit

1. Did you remove `freopen` and debug prints (or are they behind `LOCAL`)?
2. Is the multi-test line right (delete `cin >> t` for single-test problems)?
3. Are all per-test containers re-created or reset?
4. Is every product/sum in a 64-bit type where the bounds need it ([overflow](../01-Foundations/06-integer-overflow-precision-and-fast-io.md))?
5. Did you test $n = 1$, the maximum $n$, all-equal values, and negative values if allowed?
6. Java: is `out.flush()` called? Is `Arrays.sort(int[])` preceded by a shuffle?
7. Interactive: flush after every query?
8. Right language entry in the submit form (64-bit G++, Java 21)?
